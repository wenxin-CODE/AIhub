# 航天主题 Agent 项目需求文档：星枢 StarOps

推荐项目方案

1～2周 MVP

我建议你设计一款面向商业航天公司的 卫星遥感任务规划与智能数据处理 Agent 平台。

它不是简单的航天知识问答系统，而是一个能够理解航天业务需求、调用专业工具、分析约束条件、执行多步骤任务，并生成可视化结果的领域智能体。

这个项目需要重点体现四种能力：

1. Agent工程能力：LangGraph工作流、多轮推理、工具调用、状态管理。
2. 航天领域理解：卫星观测任务、遥感影像、SAR数据处理。
3. 算法能力：约束优化、图像质量分析、遥感图像处理。
4. 软件工程能力：前后端分离、异步任务、数据库、可视化和系统集成。

结合你的简历，我认为这个方向有较好的项目价值：你有推荐算法排序优化经验、Java推荐引擎开发经验、LangChain Agent项目经验，以及ScanSAR图像扇贝效应抑制专利。这个项目能够把这些经历连接起来，而不是重新做一个与你过去经验无关的项目。

### 1. 项目定位与核心亮点

#### 1.1 项目背景

随着商业航天和遥感卫星的发展，卫星观测任务涉及观测区域、卫星资源、空间分辨率、观测时间、成像模式等多种约束条件。

传统业务系统通常依赖人工查询卫星资源、筛选观测窗口、校验任务约束和编制任务方案。

本项目引入大语言模型Agent，将自然语言需求转换为结构化任务，通过工具调用、工作流编排和算法计算，实现卫星观测任务规划及SAR遥感影像辅助分析。

#### 1.2 核心定位

构建一个具备以下能力的航天领域智能体：

- 理解用户提出的卫星观测需求。
- 自主选择和调用领域工具。
- 根据工具执行结果进行多步骤分析。
- 支持多轮对话和任务约束动态调整。
- 生成可解释的任务规划方案。
- 对SAR遥感影像执行质量分析和基础处理。

#### 1.3 项目技术亮点

| 技术方向   | 展示内容                                   |
| ---------- | ------------------------------------------ |
| Agent编排  | 基于LangGraph构建状态化工作流              |
| 多轮推理   | 支持任务需求补充、约束修改和重新规划       |
| 工具链集成 | 卫星查询、观测窗口查询、约束校验、图像分析 |
| 算法应用   | 多目标评分、候选方案排序、SAR图像处理      |
| 领域数据   | 卫星资源数据、观测窗口数据、SAR影像        |
| 前端交互   | 地理信息地图、任务时间轴、图像分析面板     |
| 工程化     | 前后端分离、异步任务、日志记录、异常处理   |

### 2. 核心功能模块

#### 2.1 模块一：卫星遥感任务规划 Agent

**功能目标：**

根据用户自然语言描述，自动生成符合约束条件的卫星遥感观测任务方案。

**（1）输入**

用户自然语言输入，例如：

> 规划一次北京区域的遥感观测任务，未来3天内完成，要求空间分辨率优于2米，优先选择光学卫星。

系统需要提取以下参数：

| 参数       | 示例     |
| ---------- | -------- |
| 观测区域   | 北京     |
| 任务时间   | 未来3天  |
| 卫星类型   | 光学卫星 |
| 空间分辨率 | 优于2米  |
| 优先目标   | 尽早完成 |
| 任务优先级 | 高       |

如果用户没有提供必要参数，Agent应主动询问，而不是自行假设。

**（2）Agent处理逻辑**

采用LangGraph构建任务规划工作流：

1. 需求解析节点（Requirement Parser）

   利用LLM解析用户输入，提取观测区域、时间范围、分辨率等参数，形成结构化任务需求。

2. 卫星资源查询节点（Satellite Query）

   调用卫星资源查询工具，根据卫星类型、分辨率和成像模式筛选候选卫星。

3. 观测窗口查询节点（Observation Window）

   查询候选卫星在指定时间范围内的模拟过境窗口和可观测时间段。

4. 约束校验节点（Constraint Validation）

   对候选方案进行约束检查，过滤不符合空间分辨率、时间和成像模式要求的候选项。

5. 方案优化节点（Plan Optimization）

   使用Python算法计算候选方案评分，根据任务紧迫程度、观测时间、分辨率等指标排序。

6. 结果生成节点（Plan Generation）

   将计算结果交给LLM整理，生成任务规划报告，并说明候选方案的优缺点。

7. 人机交互节点（Human Interaction）

   支持用户修改约束条件，重新执行相关节点。

**（3）Agent工具设计**

| Tool                      | 功能         | 输入               | 输出       |
| ------------------------- | ------------ | ------------------ | ---------- |
| query_satellites          | 查询卫星资源 | 卫星类型、分辨率   | 卫星列表   |
| query_observation_windows | 查询观测窗口 | 卫星ID、区域、时间 | 候选窗口   |
| validate_constraints      | 约束校验     | 任务参数、候选窗口 | 校验结果   |
| calculate_plan_score      | 方案评分     | 候选方案           | 评分和排名 |
| generate_task_report      | 生成任务报告 | 最终方案           | 规划报告   |

**（4）输出**

- 候选卫星列表。
- 可用观测窗口。
- 候选方案评分和排名。
- 任务约束满足情况。
- 最优推荐方案。
- 任务规划报告。

**（5）MVP与进阶功能**

MVP：

- 预置5～10颗模拟卫星资源。
- 使用预生成的模拟观测窗口数据。
- 实现自然语言需求解析。
- 实现卫星查询和约束过滤。
- 实现候选方案评分和排序。
- 支持至少两轮任务条件修改。

进阶：

- 接入真实卫星轨道数据。
- 基于TLE和轨道传播计算过境窗口。
- 引入多目标优化算法。
- 支持多卫星协同观测。
- 支持任务冲突检测和资源占用分析。

说明：MVP中的观测窗口采用明确标注的模拟数据，不宣称具备真实卫星实时调度能力。

#### 2.2 模块二：SAR遥感影像智能分析 Agent

**功能目标：**

通过Agent调用图像分析和处理工具，实现SAR遥感影像质量诊断、处理流程推荐和处理结果展示。

**（1）输入**

- SAR遥感影像文件。
- 用户自然语言分析需求。

示例：

> 帮我分析这张SAR影像，判断是否存在明显斑点噪声和条纹效应，并推荐合适的处理方法。

**（2）Agent处理逻辑**

1. 影像读取节点（Image Loader）

   读取用户上传的影像，解析格式、宽高、数据类型等信息。

2. 质量检测节点（Image Quality Assessment）

   调用图像分析工具，计算灰度分布、局部方差、噪声估计值等指标。

3. 问题诊断节点（Image Diagnosis）

   根据检测指标和用户需求，判断可能存在的图像质量问题。

4. 处理方案选择节点（Processing Selection）

   根据诊断结果选择图像处理工具，例如：

   - 中值滤波。
   - Lee滤波。
   - 自适应滤波。
   - 基础条纹强度检测。

5. 图像处理节点（Image Processing）

   调用Python图像处理模块，执行相应操作。

6. 结果评估节点（Result Evaluation）

   对比处理前后的图像指标，输出处理结果和指标变化。

7. 报告生成节点（Report Generation）

   使用LLM生成结构化图像分析报告。

**（3）Agent工具设计**

| Tool                     | 功能             |
| ------------------------ | ---------------- |
| read_image_metadata      | 读取影像元数据   |
| calculate_image_metrics  | 计算图像质量指标 |
| detect_striping          | 基础条纹特征检测 |
| apply_speckle_filter     | 执行斑点噪声滤波 |
| compare_image_quality    | 对比处理前后指标 |
| generate_analysis_report | 生成分析报告     |

**（4）输出**

- 原始影像预览。
- 影像基本信息。
- 图像质量检测指标。
- 问题诊断结果。
- 推荐处理流程。
- 处理后影像。
- 前后对比报告。

**（5）MVP与进阶功能**

MVP：

- 支持PNG、JPG、TIFF等常见影像格式。
- 实现基础元数据解析。
- 实现灰度统计、局部方差等质量指标。
- 实现中值滤波或Lee滤波。
- 实现处理前后图像对比。
- Agent根据检测结果选择处理工具。

进阶：

- 使用GDAL、Rasterio处理GeoTIFF。
- 增加SAR图像专业质量评价指标。
- 引入深度学习图像去噪模型。
- 结合ScanSAR扇贝效应抑制专利研究开发专项算法。
- 支持地理坐标和空间信息可视化。

注意：基础条纹检测仅用于演示图像异常分析，不等同于完整的ScanSAR扇贝效应识别算法。

#### 3.1 Agent状态设计

使用LangGraph StateGraph定义统一任务状态：

- messages：对话历史。
- task_type：任务类型。
- task_requirements：结构化任务需求。
- satellite_candidates：候选卫星。
- observation_windows：候选观测窗口。
- planning_result：任务规划结果。
- image_metadata：影像元数据。
- image_metrics：影像质量指标。
- processing_result：图像处理结果。
- execution_status：当前执行状态。

两个Agent可以共享会话基础设施，但各自使用独立的任务状态和工具集。

如果后续希望进一步体现Java工程能力，可以增加Spring Boot业务服务，但不建议放进第一版MVP。

#### Demo一：卫星观测任务规划

用户输入：

## 三、最关键的技术实现建议

上面是完整需求，但如果要在1～2周内完成，我建议你特别控制三个地方。

### 1. Agent不要只做成LLM + Tool Calling

这是整个项目最值得体现技术深度的地方。

建议采用LangGraph，而不是简单地让模型连续调用几个工具。

推荐的Agent架构

用户输入

自然语言任务需求 

Requirement Parser

LLM提取结构化参数

Planner

决定工具调用顺序和执行策略

Satellite Tools

卫星查询、窗口查询、约束校验

SAR Tools

影像分析、滤波、指标计算

Result Evaluator

检查工具结果、判断是否满足约束

Response Generator

输出可视化结果和专业报告

其中最重要的是 Result Evaluator。

例如，用户要求分辨率优于2米，但工具返回的所有卫星都不满足要求，Agent应该明确告知用户当前没有符合全部约束的方案，并询问是否放宽条件。

而不是让LLM直接生成一个看似合理的答案。

### 2. 把Agent和算法计算分开

这是面试时可以重点讲的设计原则。

| 工作内容       | 负责组件       |
| -------------- | -------------- |
| 理解自然语言   | LLM            |
| 拆解用户任务   | LangGraph      |
| 选择工具       | Agent          |
| 查询卫星资源   | Python Tool    |
| 校验任务约束   | 确定性算法     |
| 候选方案排序   | Python优化算法 |
| 解释规划结果   | LLM            |
| 生成可视化数据 | 后端业务服务   |

不要让LLM自己计算卫星过境时间、空间分辨率或方案评分。

LLM负责理解、决策和组织流程，专业工具负责计算，业务规则负责约束校验。

这会让你的Agent更接近真实工业应用，而不是一个聊天机器人。

### 3. 必须展示执行过程，而不仅是最终答案

建议前端有一个专门的Agent执行监控区域：

Ground Software | Lockheed Martin

[lockheedmartin.com](https://www.lockheedmartin.com/en-us/products/satellite-software.html?utm_source=chatgpt.com)

至少展示：

- 当前执行节点。
- 工具名称。
- 工具输入参数。
- 工具返回结果。
- 执行状态。
- 节点耗时。

这样面试官可以看到Agent确实在执行任务，而不是把所有逻辑藏在一次LLM调用里。

## 五、我对项目的最终取舍建议

考虑到你只有1～2周开发时间，我建议实际执行时采用下面的优先级：

| 功能                       | 优先级 | 时间预算 |
| -------------------------- | ------ | -------- |
| LangGraph任务规划Agent     | P0     | 2天      |
| 卫星资源和观测窗口工具     | P0     | 1天      |

| SAR影像分析和滤波          | P1     | 2天      |
| 项目测试、部署和文档       | P0     | 1天      |

我的建议是：如果时间不足，宁可把SAR分析做成一个简单但真实可运行的独立功能，也不要为了追求功能数量，做出两个只能演示静态结果的Agent。

最终要让面试官看到三个东西：

1. 你能够独立设计一个完整的Agent系统，而不只是调用大模型API。
2. 你能够将算法、专业工具和业务规则整合成一个可执行的工作流。
3. 你理解航天遥感业务，能够把软件工程和AI能力应用到具体领域。

这三个证明，比单纯展示一个接入DeepSeek的航天知识问答机器人更有说服力。
