## 规划 Agent 算法现状核查 + 打分粒度缺陷修复

### 核查结论：没有融合任何经典规划算法
全项目 grep 无 `ortools / pulp / scipy.optimize / networkx`，也无匈牙利、NSGA-II、模拟退火、A*、CP-SAT、ILP 的实现。

当前三层全是**规则 + 启发式**：
1. **候选生成** = 笛卡尔积（satellite × window），`build_candidate_plans`，无搜索/无剪枝/无邻域
2. **硬约束校验** = 6 条手写 `if` 规则（分辨率/类型/数据质量/云量/入射角/时间范围），本质是**过滤**不是**约束求解**（无传播、无回溯、无可行性证明）
3. **排序选型** = 多目标加权求和（WSM）+ 降序 + 取第一名，权重 0.35/0.25/0.20/0.20 硬编码

即 **Filter + Weighted Sum Model** 的最简 MCDM 形态。规模小时够用，但无冲突消解（资源争抢未建模）、无帕累托前沿、无量纲统一。

### 修掉的真实 bug：可行方案被静默丢弃
- **现象**：北京区域硬约束校验出 3 个可行方案，只有 2 个进入排行（丢失 `SAT-008-48ea43`）。
- **根因**：`calculate_plan_score` 用 `win_by_sat = {x["satellite_id"]: x for x in windows}` 字典推导聚合窗口，**每颗卫星只保留最后一个窗口**。SAT-008 有 2 个窗口，保留的那个（d06393）恰被硬约束拒绝 → plan_id 对不上 `viable_plan_ids` → 该卫星全部可行方案被跳过。
- **修复**：打分改为**方案粒度**，与 `validate_constraints` 共用 `build_candidate_plans` 同一套配对逻辑，plan_id 精确对齐。
- **验证**：CN-BJ 丢失数 1 → 0；新增 2 个回归测试（`test_viable_plans_are_not_dropped_by_scoring` / `test_multi_window_satellite_yields_multiple_scored_plans`）；**51 passed**。

### 融合建议（待用户确认后再动）
- 短期：评分量纲统一（min-max 归一化）+ 引入资源冲突约束（数传窗口/能量/存储）→ 可上最大权匹配（匈牙利）
- 中期：接 **OR-Tools CP-SAT** 做真正的多星多窗口任务指派；正确姿势是 **LLM 负责把自然语言转成 CP-SAT 模型，经典求解器负责求解**——正好契合项目"LLM 只编排不算"的主张
- 与 v1.1 文档 §4.1 真实业务约束接入（P0）天然合并

### 匹配度结论：**部分匹配——方法论同构，工程实体不同构**
六维对比（任务目标/输入数据/调度对象/约束条件/评价指标/代码结构）逐项写入 `StarOps_merged_plan.md` §4.5.1。原架构三项**硬缺口**：

**处理方式：先补齐三项前提，再引入三阶段骨架。**

### 已吸收（已实现）
- **AS / VS / ES 三阶段顺序决策**：卫星集 → 窗口集 → 精确观测时刻，每阶段输出即下阶段结构化输入
- **CV**：`ConstraintVerifier` 独立于决策器的第二套实现，交叉验证后否决（`VERSION="tslc-cv-v1"`）
- **PM**：`PerformanceManager` 迭代验证 + 重规划，上限 3 次；失败写 MS，成功写 K
- **MS / K**：`schedule_memory` / `schedule_knowledge` 两张表
- **资源独占 + 姿态转移**：`satellite.transition_time_min` / `min_imaging_duration_min` + 占用表
- **AGENT_PROMPTS**：AS/VS/ES/CV/PM 各自的 name/ability/responsibilities，对应论文 Fig.4
- **人工审批关口保留**（论文没有这一环）——本项目安全承诺决定的有意偏离

### 本轮修掉的真实缺陷（都是"点了没反应"级别）
1. **LangGraph 路径从未真正跑通**：节点签名 `(state, tracer)` 与框架不兼容（`node_route() missing 1 required positional argument: 'tracer'`）+ Annotated 追加 reducer 导致列表重复。此前被 langgraph 未安装时的 `run_builtin` 降级掩盖。
2. **`calculate_plan_score` 静默丢可行方案**（每星只留最后一个窗口）→ 改方案粒度打分。
3. **`DEFAULT_ORDER_FIELDS` 里 `area_id: ""` 覆盖传入值** → 所有订单区域被置空，区域约束整体失效，完成率虚高 4/6。
4. **ES 阶段缺 `stage_decision` 事件** → 前端看不到精确时刻决策。
5. **ES 失败时排除整颗卫星**（过度排除，误杀可排期订单）→ 改为只排除该窗口。
6. **拒绝原因只反映最后一次尝试**（根因被覆盖）→ 加 `stage_reasons` 跨尝试累积。
7. **`req.order_ids` 是死代码**（查出来的 rows 没用）→ 现在显式塞进 `state["orders"]`。
8. **二次调度队列为空**（订单状态已变 scheduled/rejected）→ 新增 `reset` 参数 + 前端「重置队列后调度」勾选。
9. **`node_route` 会用 LLM 结果覆盖调用方预设的 `task_type`** → 一旦 LLM 误判，请求会进错主干。改为**预设值优先**。
10. **模拟窗口不可重复**：窗口 ID 用随机 UUID + 时间基准取 `datetime.now()`，每次重启数据全变，"演示结果可重复"名不副实，且 K 的计划指纹无法跨重启去重 → 改为 **窗口 ID 由「卫星|区域|起始时刻」sha1 派生 + 时间基准锚定当日 UTC 零点**。
11. **K 无去重**：同一条计划每次确认都新增一行 → 加 `plan_signature` 列 + 部分唯一索引 + upsert。**索引必须建在补列之后**（`KNOWLEDGE_INDEX_SQL` 在 `_apply_migrations` 之后执行，否则旧库启动直接失败）。
12. **窗口重建后留下失效知识**（指向不存在的窗口）→ `_prune_stale_knowledge`。
13. **模拟数据与约束不自洽**：云量 Beta(2,5) 近半超 30% 阈值、窗口 8–15 min 短于最短成像时长、订单 3–7 天落在窗口覆盖外 → 分别改为 gauss(0.22,0.16) / 20–45 min / 12–14 天。
14. **Element Plus 图标从未全局注册**（`<DataAnalysis />` 被当未知元素渲染为空）→ `main.ts` 循环注册全部 icons。
