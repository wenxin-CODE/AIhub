# 星枢 StarOps

> Satellite Mission Intelligence Platform —— 面向商业航天求职展示的 Agent 原型

以大语言模型 Agent 负责任务理解与工具编排，以确定性 Python 工具负责计算与校验，
**规划与执行彻底分离**，人工审批后方可落库，全程双表留痕可追溯。

## 快速开始

### 环境要求

- Python 3.13（项目自带虚拟环境 `starops/.venv`，已装好全部依赖）
- Node.js 18+（开发于 22）

> **为什么用项目内虚拟环境**：本机 conda 环境里 `fastapi` / `numpy` / `opencv` / `pytest`
> 分散在不同解释器中，直接 `pip install` 到全局会互相污染、且换机不可复现。
> `starops/.venv` 由 `uv` 创建，锁定在 Python 3.13，与 `requirements.txt` 一一对应。

### 后端

```bash
cd starops/backend

# 方式一（推荐）：用项目自带虚拟环境
../.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000

# 方式二：从零重建虚拟环境
cd starops
uv venv .venv --python 3.13
uv pip install --python .venv -r backend/requirements.txt
```

> `.wheels/` 里缓存了 numpy / opencv 等大包 wheel，PyPI 慢时可离线安装：
> `uv pip install --python .venv --no-index --find-links .wheels numpy opencv-python-headless`

首次启动会自动建表并写入模拟数据（8 颗卫星 + 48 条观测窗口 + 6 条观测订单）。

> **DeepSeek 配置（可选）**：复制 `.env.example` 为 `.env` 并填入 `DEEPSEEK_API_KEY`。
> 不配置也能完整演示——此时需求解析走离线规则降级，界面顶部会显示「LLM 离线降级模式」标签。

> **OpenCV 配置（可选）**：SAR 的全部算法（局部方差、ENL、Lee / 中值 / 自适应滤波、
> FFT 条纹检测、PSNR / SSIM）都是**纯 numpy 实现**，自带 PNG 编解码。
> OpenCV 只用于读取 TIFF / GeoTIFF 等更多格式，缺失时演示链路完全不受影响。

### 前端

```bash
cd starops/frontend
npm install
npm run dev
```

访问 http://localhost:5173 ，Vite 已配置 `/api` 与 `/files` 代理到 127.0.0.1:8000。

### Docker Compose

```bash
cd starops
docker compose up -d
```

## 演示动线

### 一、规划 Agent（工作台）

1. 打开 **工作台**，输入：
   > 帮我规划一次北京区域的卫星观测任务，要求空间分辨率优于2米，尽量在未来3天内完成，优先选择光学卫星。

2. 观察右侧「Agent 执行过程」逐条推进：
   `意图识别` → `需求解析` → `卫星资源查询` → `观测窗口查询` → `硬约束校验` → `方案评分与排序` → `结果生成` → `人工审批关口`

3. 中间面板可展开每个工具的**入参与返回**及耗时。

4. 右侧「结构化结果」显示约束校验状态、候选方案评分表、观测窗口数据质量标记。

5. **审批面板出现**——执行按钮不可用。切到「审批中心」批准后返回工作台。

6. 切到「审计追溯」页，可见工具调用表与业务审计表的完整链路。

### 二、SAR Agent（SAR 影像分析页）

1. 上传（或选择）一张 SAR 影像。仓库自带演示影像：`starops/data/images/demo_sar.png`（512×512，含乘性斑点噪声 + 水平条纹）。

2. 执行过程逐条推进：
   `意图识别` → `SAR 影像分析`（元数据 → 质量指标 → 条纹检测 → 诊断 → 管线横评 → 审批单）

3. **诊断结论**：本例判为「斑点噪声严重（CV=0.755，ENL=2.21）」+「检测到水平条纹（突出度 0.445）」。

4. **候选管线横评**（同一套指标口径）：

   | 管线 | 结果 | 说明 |
   |---|---|---|
   | Lee 滤波 | **已选中** | CV 0.7548→0.5636（降 25.3%），均值偏移 0.61% |
   | 中值滤波 | 已淘汰 | 均值偏移 12.8% 超过 5% 阈值（辐射强度失真） |
   | 自适应滤波 | 已淘汰 | 降噪效果弱于最优管线（0.8% vs 25.3%） |

5. 审批单生成，处理管线挂起——切到「审批中心」批准后方可正式执行。

### 三、订单驱动调度（订单调度页）

方法论来源：IEEE TGRS《A Tri-Stage LLM-Coordinated Framework for Order-Driven Scheduling of Earth Observation Satellite Tasks》（DOI `10.1109/TGRS.2026.3700605`）。本项目**吸收其三阶段骨架与外部校验思路**，未复现其全局利润最优模型（详见下文「与论文的关系」）。

1. 打开 **订单驱动调度** 页，左侧是订单队列（优先级 / 利润 / 区域 / 时间范围 / 最小时长 / 云量上限），右上「运行订单调度」触发 SSE。

   > 勾选「**重置队列后调度**」可重复执行（订单排期后状态即变为 scheduled/rejected，
   > 不重置则第二次运行队列为空）。在订单表格里勾选若干订单，则只调度所选订单。

2. 中部面板逐条推进**三阶段决策流**，每一步都带决策依据：

   | 阶段 | 决策内容 | 输出 |
   |---|---|---|
   | **AS** 指派卫星 | 为订单选星 | 候选卫星 + 打分明细 |
   | **VS** 选择时窗 | 在星上选有效观测窗口 | 窗口 + 过滤理由 |
   | **ES** 精确时刻 | 在窗口内定观测时刻 | 精确起止时刻 + 姿态转移余量 |

3. **CV 校验器独立核验**：`ConstraintVerifier` 不参与决策，只负责否决，与三阶段决策器是两套独立实现。

4. 右上 8 张指标卡：完成率 / 已排期 / 已拒绝 / 约束违规 / 重规划次数 / 原子决策数 / 总效用 / 耗时。

5. **可解释拒绝**：不可行订单不会被静默丢弃，逐条给出根因（云量超限 / 数据质量存疑 / 时间范围不匹配…），且根因按阶段跨尝试累积，不会被最后一次失败覆盖。

6. **MS / K 双 Tab**：
   - **MS 失败尝试记忆**——记录每次失败的订单、阶段、尝试次数与原因，用于下次避坑；
   - **K 已确认计划知识库**——按计划指纹（卫星 | 窗口 | 起止时刻）去重保存成功计划，
     同一条观测计划只保留一条。

7. 与论文方法的差别在页面上是**可见的**：本页展示的是逐单贪心 + 可解释拒绝，而论文追求全局利润最优。页面上不出现任何论文的性能提升数字。

#### 与论文的关系（对外表述口径）

| 维度 | 论文做法 | 本项目做法 |
|---|---|---|
| 决策结构 | AS → VS → ES 三阶段 | **已吸收**，同一骨架 |
| 约束校验 | 分阶段独立校验（CV） | **已吸收**（`ConstraintVerifier`） |
| 失败记忆 / 计划知识 | MS / K | **已吸收**（`schedule_memory` / `schedule_knowledge` 表） |
| 资源独占 / 姿态转移 | 显式建模 | **已吸收**（`satellite.transition_time_min`、`min_imaging_duration_min` + 占用表） |
| 优化目标 | **全局利润最优** | ❌ 逐单贪心，优先级→利润是**项目自设映射表**，非真实现金流 |
| 规模 | 真实星座规模在线调度 | ❌ 8 星 / 48 窗口 / 6 单的模拟规模 |
| 转移时间 | 真实姿态转移时间矩阵 | ❌ 每星一个标称值 |
| 性能提升数字 | 论文报告 4.58% / 13.38% | ❌ **不引用**（未复现其评测基线，无同口径证据） |

### 关键演示点

| 要点 | 怎么体现 |
|---|---|
| Agent 自主选工具 | 执行过程面板逐条出现 tool 名称 |
| 工具结果参与推理 | 校验节点的 violations 直接来自工具返回 |
| 硬约束独立于 LLM | 校验器是纯 Python，`validate_constraints` 工具可独立测试 |
| 审批不可绕过 | 后端 `commit_plan` 强制校验审批状态，绕过前端直接调用也会被拒 |
| 幂等保护 | 同一幂等键重复提交返回首次结果，`plan_commit` 只增 1 条 |
| 数据质量标记 | 观测窗口表 `quality` 字段：FRESH / STALE / EXPIRED / SUSPECT |
| **管线由实测选出** | 候选逐条实跑，统一指标横评择优，不由 LLM 指定 |
| **降噪不破坏辐射强度** | 5% 均值守门拦下均值偏移 12.8% 的中值滤波 |
| **落选可解释** | 每条被拒管线都带原因，推到前端可见 |
| **条纹仍走经典方法** | FFT 谱峰突出度检测，不硬上深度学习 |
| **三阶段顺序分解** | AS→VS→ES 每阶段输出即下阶段结构化输入，可单测 |
| **校验器独立于决策器** | `ConstraintVerifier` 交叉验证 AS/VS/ES 结果，只否决不决策 |
| **不可行订单根因可见** | PM 重规划上限 3 次，超限必带根因拒绝，根因按阶段累积 |
| **失败经验被记住** | MS 记录失败尝试，K 按计划指纹复用成功计划 |

## 安全闭环设计

这是本项目的核心竞争力，不是"接入了一个大模型"。

```
生成 → 硬约束校验 → 人工审批 → 执行（校验状态+版本+幂等键）→ 双表留痕
         ↑                                    ↓
    独立于 LLM                        重复提交幂等命中
```

规划链、SAR 链与订单调度链**共用同一套审批关口**——处理管线与调度计划同样需要人工批准才能落地。

| 机制 | 实现位置 | 验证方式 |
|---|---|---|
| 审批关口 | `services/approval.py` | 未审批调用 `commit_plan` → 返回 failed + 写审计 |
| 硬约束校验器 | `tools/planning.py` | 纯代码，不接受 LLM 输出作为判定依据 |
| 调度约束校验器 | `tools/order_scheduling.py`（`ConstraintVerifier`） | 独立于 AS/VS/ES 决策器，交叉验证后否决 |
| 资源独占 / 姿态转移 | `database.py` + `tools/order_scheduling.py` | 同星同时刻单任务；相邻任务留 `transition_time_min` |
| 审计双表 | `database.py` | `tool_execution`（工具）+ `audit_log`（业务） |
| 幂等键 | `build_idempotency_key` | `hash(task_id + plan_version + 归一化约束)` |
| 数据质量标记 | `observation_window.quality` | EXPIRED 硬性排除且必须被报告 |
| 辐射强度守门 | `agents/nodes/sar_nodes.py` | 均值偏移 > 5% 的管线淘汰并记录原因 |

## 测试

```bash
cd starops
./.venv/Scripts/python.exe -m pytest tests/unit -v
```

当前 **71/71 通过**（5 个测试文件），覆盖 T01–T29 验收用例。包含三条**跨路径一致性护栏**：
1. 自带 PNG 解码器与 OpenCV 解码结果必须逐像素一致，同图在有无 OpenCV 的机器上
   指标完全相同——否则"同一张图不同机器不同结论"，横评不可信；
2. 多窗口卫星必须产出多条被评分的可行方案——否则评分器会静默丢弃候选；
3. 模拟窗口必须在同一天内重复生成时**完全一致**（ID 与时刻都一致）——否则
   "演示结果可重复"名不副实，知识库 K 的计划指纹也无法跨重启去重。

订单调度另含 18 项专项单测，覆盖三阶段决策、CV 独立性、资源冲突、PM 重规划、
不可行订单可解释拒绝、MS/K 更新与指纹去重、指标一致性、空队列与事件流三阶段覆盖。

## 边界声明

- 所有卫星、观测窗口、订单数据均为**明确标注的模拟数据**（`source='simulated'`），不宣称真实卫星实时调度能力。
- SAR 演示影像为**模拟生成**（乘性斑点噪声 + 人工条纹），不是真实卫星回传数据。
- 不实现真实卫星遥控、任务下发、轨道控制与资源预约。
- 未配置 DeepSeek Key 时，需求解析由规则降级处理，界面与报告会明确标注"非真实模型推理"。
- 图像分析结果不作为真实航天任务决策依据。
- L2 深度去噪模型尚未接入，当前所有横评结论仅在 L1 经典基线之间成立。
- **订单调度为逐单贪心，不是全局最优**；优先级→利润映射是项目自设的效用模型，
  不代表真实商业合同的收益结构。
- **姿态转移时间为每星一个标称值**，不是真实卫星的姿态转移时间矩阵。
- **未复现 IEEE TGRS 2026 论文的全局利润最优模型与评测基线**，其报告的性能提升
  数字（4.58% / 13.38%）在本项目中**不引用、不复述**——没有同口径实验就没有资格引用。
